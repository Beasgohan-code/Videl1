# Group knowledge

A group-visible, manually maintained FAQ, isolated by the current bot and group. Nothing is captured automatically. Every member of the group can see entries, including content saved by replying to a message; do not save secrets, private reports or sensitive personal data. Telegram group messages, forwarded copies and backups can persist after an entry is changed or deleted. This is not a private moderation casebook.

- `/faq` or `/faq list [page]` browses keys; buttons open entries and navigate pages. `/faq <key>` shows an entry and its **group-wide revision**. `/faq search <fragment> [page]` searches keys only, not text, with paginated buttons.
- An admin with Telegram's **change group info** privilege can use `/faq save <key> <text>` or reply to text/caption with `/faq save <key>`. Save is create-only and never silently replaces an existing entry.
- To change an entry, open it first and use `/faq replace <key> <revision> <text>` (or reply to text with `/faq replace <key> <revision>`). Any group FAQ change makes the revision stale; review the entry and retry. This prevents two cooperating admins from silently overwriting one another.
- `/faq rename <old-key> <new-key> <revision>` moves an existing entry without overwriting another key. Open the old entry first to review the current group-wide revision; any intervening FAQ edit makes it stale. Previously sent copies still exist.
- `/faq delete <key>` shows the exact confirmation command; `/faq delete <key> confirm <revision>` deletes only if the group-wide revision is unchanged. This explicit action is not reversible by the bot. No messages or files are automatically deleted.

Keys are case-insensitive ASCII letters, digits, `_` and `-`, 1–32 characters; `list`, `search`, `save`, `replace`, `rename` and `delete` are reserved. Text is plain, up to 700 characters; formatting is escaped. Entries are retained until an admin deletes them or the database is externally removed, with a maximum of 50 entries per bot and group. No user identities or source message IDs are stored. Empty group documents retain their revision so stale confirmations cannot act on later recreated entries.

The database document is updated using a revision compare-and-swap; bounded create retries can report contention instead of silently losing edits. Authorization is checked live on each write, but Telegram membership can change after the check and before the database write. Anonymous group-admin posts are accepted, consistent with the existing moderator verifier. Existing messages can reveal old content even after deletion. The plugin must be enabled for its commands and buttons; update all workers together. Offline tests use fake Telegram and mocked MongoDB; no real Telegram, production MongoDB, multi-worker or security audit is claimed.
