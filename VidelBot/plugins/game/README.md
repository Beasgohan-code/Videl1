# Videl Arcade

`/game` opens a single-player Tic-tac-toe board using regular Telegram inline buttons. Tap **More chat games** for Take the Last, Rock Paper Scissors and Higher or Lower: these also use ordinary Telegram buttons and do not need widget beta. Tap **Widget games** to browse the widget catalogue by category: Triple Play (Tic-tac-toe, Pairs and Lights), plus Sliding Tiles, Minefield, Sudoku 4×4, Maze, Merge 128, Connect Four, Take the Last, Rock Paper Scissors, Word Rescue, Mini Reversi, Snake, Target Tap, Reaction Test, Number Rush, Pattern Memory, Math Sprint, Word Scramble, Quick Trivia, Higher or Lower, Code Breaker, Tower Puzzle, Color Flood and Dots & Boxes. Puzzle Trio puts Sliding Tiles, Minefield and Maze into one widget with instant local tabs (switching resets the current puzzle). All are small, self-contained touch games; the timing games have explicit start or restart controls, and Snake and Target Tap also have pause controls.

## Source layout

The source is intentionally split: `shell.html` and `arcade.html` contain the markup; `arcade.css`, `classic.css` and `tabs.css` contain the styles; `engine.js`, `classic.js`, and the gameplay files in `games/` and `tabs.js` contain the gameplay and UI logic. `plugin.py` assembles the selected trusted local files into a single widget document when sending. This is necessary because the Telegram widget sandbox does not fetch external stylesheets or scripts. Template markers and closing tags are checked before assembly, and the final raw and compressed sizes are checked before sending.

## Availability and safe opt-in

Widget support is experimental. The provided [Telegram widget format](https://github.com/TelegramMessenger/widget-sandbox/blob/main/docs/tgw-format.md#the-bot-api-104) describes Bot API 10.4 beta; Videl's bundled aiogram targets Bot API 10.3. The implementation uses an aiogram `TelegramMethod` for an **outgoing** `sendWidget` call only. It checks that incoming and outgoing bot IDs match, carries a topic ID when present, includes a caption for older clients, uses no query permissions, and does not run a competing receiver. The regular command and menu callbacks remain on Videl's existing WzGram receiver. With widget beta explicitly enabled, the default widget-only sender uses a separate short-lived aiogram session at `https://api.telegram.org/beta`; other Bot API calls still use the existing bridge and its configuration. This is the beta *API base*, not Telegram's separate `/test` environment. The beta API and client eligibility may change.

`GAME_WIDGETS_BETA` defaults to false. Set it to `True` only after checking the current Telegram specification and testing with an isolated bot and compatible clients. `GAME_WIDGETS_API_MODE=beta` is the default for widget sends; `configured` instead uses the existing aiogram bridge and its `BOT_API_URL` (or standard Bot API). Unknown modes fail closed. The flag does not alter the incoming receiver, webhook, or normal Bot API endpoint. `AIOGRAM_ENABLED` must also be enabled and the primary bot must be configured. A normal or custom Bot API endpoint that lacks `sendWidget`, an incompatible client, or a timeout may prevent the widget appearing. Failures never log the exception text, since it can contain credentials. The four chat-button games remain available. On older Telegram clients the widget itself may appear unsupported; the separate chat board is the fallback. Setting the flag does not upgrade Telegram clients or make production API support available.

No game requires a network connection inside the widget, bot queries, external images, custom fonts, or third-party JavaScript. Unlike the Widget Lab menu, our chat-button catalogue sends a new widget without deleting the existing board; Puzzle Trio uses local tabs within one immutable document. Query-driven menus, shared state and multiplayer would require a compatible receiver and timely answers, and are not implemented. The compact inline vector icons are original to this plugin. Each viewer plays locally; the games do not implement multiplayer, leaderboards, rewards, server scores or shared progress. Current games are memory-only. Number Rush, Math Sprint and Quick Trivia optionally store a personal best in the widget client’s local storage for that message and device. Tap **Clear best** in the relevant game to remove it. If storage is unavailable or full, gameplay still works without a saved best. The client may remove this storage when the message or cache is deleted; it is not synced to the bot, other messages or devices. Chat boards are encoded in their buttons and tied to the initiating user; simultaneous taps on stale buttons may race, especially across workers. They are casual games, not authoritative records. No game data is saved to MongoDB. In topic chats the bot uses the topic identifier when provided by the incoming client.

The widget profile currently describes touch interactions rather than normal keyboard support and does not guarantee accessibility semantics for `aria-*`. Shape and text cues accompany color, and timing games are optional, but this is not a claim of screen-reader support or WCAG conformance; native-client and accessibility testing remain necessary.

## Testing

Run `python -m pytest tests/test_game.py -q` from `VidelBot`, and `npm ci && node game-arcade.test.cjs` in `VidelBot/tests/ui`. The latter is a synthetic JSDOM gameplay suite with test-only state inspection; it is not a Telegram-client test. Python tests check chat-game rounds and isolation, catalogue filters, topic routing, size limits, opt-in, identity checks and error redaction with fake clients. Telegram's `widget-sandbox` can additionally validate the assembled HTML against its QuickJS runtime and renderer; this still does not prove live Bot API delivery or behavior in real Telegram clients. Validate the current beta endpoint, actual client versions, forum topics and old-client fallback with a separate test bot before any rollout.

Telegram permits at most 100 commands in a scope. To make room for `/game` in the owner menu, `/sh` is no longer advertised there; its existing owner-only handler is unchanged.
