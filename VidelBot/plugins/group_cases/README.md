# Private moderation casebook

A **manual** group casebook for admins to organize reports and decisions. It never bans, mutes, deletes a Telegram message, collects chat messages, reports a member, or performs any other moderation action. A case is a note, not proof that its subject did anything or that an action succeeded. It is not an immutable audit log: it records who created or last updated the case and who authored each note, but does not retain the full history of state changes.

Use `/modcase` **only in a private chat with this bot**. Provide the negative numeric group ID (e.g. obtain it with `/id` in the group). On every command and every button press, the bot verifies the caller's current Telegram group owner/admin status and `can_restrict_members` right, and the bot's current membership; it fails closed if either cannot be verified. An admin whose permission is revoked cannot make new reads or changes through this interface, though anything already sent to that admin remains in Telegram. Group message/anonymous-admin use is intentionally unsupported. There is no platform-admin or `config.ADMINS` requirement.

- `/modcase <group-id> list [open|closed|all] [page]` browses cases; buttons open records and move pages.
- `/modcase <group-id> find <user-id> [page]` lists cases for that numeric user ID, across both open and closed states. Pagination buttons are private and recheck access. The subject’s membership or conduct is not verified.
- `/modcase <group-id> open <user-id> <summary>` manually creates a case with a numeric Telegram user ID and a 1–200 character summary. The subject's membership or behavior is **not verified**.
- `/modcase <group-id> show <case-id> [note-page]` shows the summary, state, creator, last updater, UTC times and current **group-wide casebook revision**. Notes display one per page.
- `/modcase <group-id> note <case-id> <revision> <text>` adds a 1–400 character note. Each note records its author's Telegram user ID and timestamp. Up to 20 notes per case are retained.
- `/modcase <group-id> close|reopen <case-id> <revision> confirm` changes the recorded state only. Any other casebook update invalidates the revision, so reopen the case and review before retrying.
- `/modcase <group-id> purge <case-id>` previews deletion. `/modcase <group-id> purge <case-id> <revision> confirm` irreversibly removes that case and notes from the active casebook if the revision is unchanged. A stale confirmation cannot remove a newly changed case. Copies in Telegram, logs outside the plugin, backups, replicas or database snapshots can remain.

Records contain the supplied subject ID and text, administrator IDs, timestamps and state. **Do not put passwords, tokens or other secrets in the casebook.** The plugin does not encrypt these records itself: database operators, hosting administrators and backup readers may have access. Data is scoped by bot ID and group ID and retained until an authorized admin explicitly purges it or the database is externally removed; nothing is automatically deleted. Maximum 100 cases per bot/group; removing records requires deliberate review. Empty group documents retain their revision to help prevent stale confirmations. The private command is not added to the private Telegram menu because the owner scope is already at Telegram's 100-command limit; type it directly.

Revision compare-and-swap and bounded retries reduce accidental overwrites among cooperating workers but cannot create a transaction with Telegram. Permission can change after verification and before a database operation or response; an in-flight read can return old data. Concurrent or mixed-version deployments, real MongoDB contention, live Telegram, backups, scale and security have not been independently verified. Update all workers together. Disable the plugin to disable its command and buttons; this does not erase stored records.
