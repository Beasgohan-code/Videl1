# Telegram clone directory and backend encryption

The existing Vercel front door proxies requests to the Python backend; it does not need `ENCRYPTION_KEY`. The backend host needs a valid Fernet `ENCRYPTION_KEY` before the Studio can save a bot token. If the application has ever stored encrypted credentials, restore the **same original key** from the backend's secure secret store or backup. Replacing it makes existing encrypted values unreadable; changing a key is not a migration. Do not paste keys or bot tokens into support chats, URLs, screenshots, or logs. If no encrypted credentials exist and this is a fresh installation, an operator can generate a Fernet key privately using the cryptography library and store it in the backend host's secret configuration. Restart the backend according to the host's instructions. Token-free draft bot records do not require this key. The legacy clone engine may store new secrets in plaintext if encryption is missing, so restore/configure encryption before adding sensitive credentials there too; this change does not migrate existing plaintext records.

The account's Telegram `/clone` registrations are separate from workspace records. In Bot Management use **Show my Telegram clones**, after signing in with a personal Telegram one-time link or signed Mini App launch. The account-only read queries the File Store database (`FS_DB_NAME` / File Store Mongo configuration); it shows at most 100 non-deleted records. "Enabled in registration" is not proof of a running worker. Missing records may be on a different backend/database, registered to a different Telegram account, deleted, or outside the first 100. Database failures are reported instead of treated as an empty list. A legacy/admin-token sign-in, API key or demo is not proof of the Telegram owner's identity and cannot use this view; sign in again with your personal Telegram link.

This view does not copy, import, edit or start bots, expose tokens, or assign a workspace. Use the existing Telegram clone controls to manage those registrations. Any future import needs explicit ownership, workspace consent, safe credential handling and concurrency review. This change needs the updated Python backend and UI deployed together; mixed/older workers can return an unavailable message. It has only been tested with synthetic sessions and mock Mongo, not a live deployment.

Focused synthetic checks: `python -m pytest tests/test_legacy_bot_directory.py` from `VidelBot/`, `node VidelBot/tests/ui/legacy-clones.test.cjs` (with the UI test dependencies and Python backend dependencies installed), and `node VidelBot/tests/browser/next-legacy-clones.test.cjs` against the isolated Next preview fixture. The Chromium check covers 320, 390 and 1440 CSS pixels; it does not validate real-device accessibility or production behavior.
